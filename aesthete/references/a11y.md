# The accessibility floor

Owns the floor: the normative values that sit at precedence 1 and are never
overridden by a brand, a supplied document, or an instruction. Every value
here is quoted from the specification, not recalled.

**Pinned to WCAG 2.2, W3C Recommendation, updated 12 December 2024**
(first published 5 October 2023). WCAG 3.0 is an early draft and is not a
Recommendation; do not apply it. WCAG 2.2 removed SC 4.1.1 Parsing, which is
obsolete and must not be cited.

**Conformance target is level AA.** AAA criteria are marked below and are
recommendations, not the floor. Never present an AAA value as required, and
never present an AA value as optional.

**Re-verify before relying on this file where the stakes are legal,
contractual, or regulatory.** A pinned date is a staleness signal, not a
guarantee: check w3.org/TR/WCAG22 and confirm the version date still matches
the pin. If it does not, the specification wins and this file is wrong.

## Contrast

| Applies to | Minimum | Criterion |
| --- | --- | --- |
| Text below the large-text threshold | 4.5:1 | 1.4.3 Contrast (Minimum), AA |
| Large text: 18pt, typically 24px; or 14pt bold, typically 18.66px | 3:1 | 1.4.3 Contrast (Minimum), AA |
| Visual information identifying a control or its state | 3:1 | 1.4.11 Non-text Contrast, AA |
| Parts of a graphic required to understand the content | 3:1 | 1.4.11 Non-text Contrast, AA |

Exempt: inactive or disabled controls; pure decoration; text that is part of
a logo or brand name; text that is part of a picture containing significant
other visual content; and graphics whose particular presentation is
essential to the information conveyed.

Consequences: a divider between two same-elevation surfaces is decoration
and is exempt, while the border that identifies where an input begins is
not. Size is part of the measurement, so one color can be compliant in a
headline and non-compliant in a button label. Measure the composited result
wherever transparency is involved.

## Target size

| Requirement | Value | Criterion |
| --- | --- | --- |
| Pointer target size | 24 by 24 CSS pixels | 2.5.8 Target Size (Minimum), **AA** |
| Pointer target size, enhanced | 44 by 44 CSS pixels | 2.5.5 Target Size (Enhanced), **AAA** |

24 by 24 is the floor. 44 by 44 is a recommendation, and the two are
routinely confused in brand documentation in both directions. SC 2.5.8
carries exceptions including sufficient spacing, an equivalent control
elsewhere on the page, inline targets within a sentence, user-agent-controlled
sizing, and cases where the presentation is essential.

## Focus

| Requirement | Criterion |
| --- | --- |
| A keyboard focus indicator is visible | 2.4.7 Focus Visible, **AA** |
| The focused element is not *entirely* covered by author-created content | 2.4.11 Focus Not Obscured (Minimum), **AA** |
| The focused element is not covered *at all* | 2.4.12 Focus Not Obscured (Enhanced), **AAA** |
| The focus indicator meets specified size and contrast | 2.4.13 Focus Appearance, **AAA** |

The AA floor forbids only total obscuring. Keeping a focused control fully
clear of sticky headers, footers, and floating panels is the AAA behavior;
adopt it as house practice, but do not describe it as the AA requirement.

## Text and reflow

| Requirement | Value | Criterion |
| --- | --- | --- |
| Text resizes without assistive technology, no loss of content or function | up to 200 percent | 1.4.4 Resize Text, AA |
| No loss of content or function when the reader overrides text spacing | line height 1.5x font size; paragraph spacing 2x; letter spacing 0.12x; word spacing 0.16x | 1.4.12 Text Spacing, AA |
| Content appearing on hover or focus is dismissible, hoverable, and persistent | | 1.4.13 Content on Hover or Focus, AA |

Captions and images of text are excepted from 1.4.4. These three together
are why type sizing uses relative units and why layouts must survive the
reader changing them.

## Input and flows

| Requirement | Criterion |
| --- | --- |
| Dragging has a single-pointer alternative, unless dragging is essential | 2.5.7 Dragging Movements, AA |
| Information already entered in a process is auto-populated or selectable, not re-entered | 3.3.7 Redundant Entry, **A** |
| No cognitive function test in authentication, unless bypassable or assisted | 3.3.8 Accessible Authentication (Minimum), AA |
| Help mechanisms appear in a consistent order across pages | 3.2.6 Consistent Help, **A** |

3.3.8 is why an authentication flow must not break password managers or
paste. 3.3.7 is why a checkout must never ask twice for the same address.
Both are commonly missed because they read as product decisions rather than
accessibility requirements.

## Not a standard

Performance targets are a vendor's product thresholds, revisable by that
vendor at any time, and carry none of the regulatory weight of the criteria
above. `platform` owns them. Never present them as a standard, and
never trade a criterion here against one of them.
